# Which job types CI's `database` job runs against real Postgres, and why each
# of the others is not run there.
#
# Every JobType in lib/queue/index.ts appears here exactly once, and the
# `db-jobs` rule holds that — so a new job type arrives as a decision, not as
# a gap nobody noticed: run it here, or say why it cannot be.
#
#   run: <type> [key=value ...]   passed to `npm run job --` as written
#   skip: <type> — <why>
#
# A run line's predicates usually match nothing on the job's empty database,
# which is fine: Postgres still plans every statement, and planning is where
# `operator does not exist: text = channel` is raised.
